# 守简 0.30.0 第三轮自检

本轮修复两类会影响可信度和真实连续语音的缺陷。它仍是独立开源教学组件，不包含主项目商业核心；真实麦克风、Google Cloud 首声和真人体验尚未验收。

## 修复与原因

1. 连续语音遇到 `no-speech` 或识别器自然结束且无文字时，过去会停在“已开启却不再收音”的状态。现在按 250 ms 起、最多 3 秒的退避重新倾听；权限/设备错误仍停止并展示错误。停止语音和手动打断会取消待重试定时器。
2. 在真实浏览器端到端测试中发现，原代码把 `window.setTimeout` / `setInterval` 保存后当作类方法调用，Chromium 抛出 `Illegal invocation`。它影响停顿自动发送、安静重听和浏览器 TTS 看门狗；Node 假定时器单测此前无法发现。现已统一通过原生 `window` 调用，新增完整的“安静结束 → 自动重听 → 语音提交 → 朗读完成 → 再次倾听”浏览器流程。
3. 已确认的原问此前被拼进系统级提示词。现在原问留在普通用户输入层，仍可用于检索和解读；服务器可信时钟、纯函数重算卦象和冻结证据仍在服务端约束层。这样降低用户输入伪装成高优先级指令的风险，但不等于可以数学证明模型绝不受提示注入影响。

## 本轮检查

- `npm test`：214 / 214 通过。
- 本机 Playwright：Chromium、WebKit 与两组移动仿真 28 / 28 通过，含新增连续语音流程；它使用假识别器和假朗读器，不替代真实麦克风与音色验收。
- 本机 Firefox 仍因 Playwright 二进制的 Windows SideBySide `mozglue` 错误无法启动；以远端 CI 的 Firefox 结果另行核对。
- `npm run eval:rag`：固定集 recall@4 与负例精度均 100%，检索均值 2.38 ms、P95 3.71 ms；这不代表模型回答准确率。`npm run check` 与 `git diff --check` 通过；`npm audit --omit=dev --audit-level=low` 报告 0 个已知漏洞。GitHub Actions 需按本版本最终提交的 run 单独核对，不沿用 0.29.0 结果。

## 验收边界

当前标准是“开源演示在受控浏览器场景能连续对话且异常后可恢复”。要说真实产品 OK，还需用户设备上进行至少三轮连续语音、一次静音重听、一次打断与 TTS 故障复验；记录 ASR、首字、播放器开声的 P50/P95，并对声音、动作及经传引用做真人审阅。收费上线另需正式域名、账号权益、供应商成本上限和运营政策。
