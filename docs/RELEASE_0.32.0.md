# 守简 0.32.0 第五轮自检

本轮处理麦克风授权等待与取消。浏览器权限请求无法由页面强制关闭，但用户取消后不应继续录音，也不应锁住文字对话。

## 修复

1. 录音器增加取消令牌。若用户离开页面或取消时授权尚未返回，迟到的麦克风流会立即释放，不创建录音器。
2. 授权等待期间，页面显示“等待麦克风授权 · 取消”，并锁住送问、导入、清空和连续语音入口。点击取消后文字输入立即恢复；浏览器授权请求返回前，录音入口保持禁用，避免重复申请。
3. 用户主动取消不再插入错误消息；页面断开时会取消录音器并释放资源。

## 验证范围

新增取消迟到授权的单测、授权等待视图契约和真实浏览器中的取消恢复流程。本地 `npm test` 218 / 218 通过；Chromium、WebKit 及两组移动仿真共 40 / 40 条浏览器流程通过。首次以 11 个并发 worker 运行时，移动 WebKit 的旧“停止长回答”流程有一次失败；单独重跑通过，降低至 4 个 worker 后全量通过，未把首次失败隐藏为一次性全绿。`npm run eval:rag` 的固定集 recall@4 与域外负例精度均为 100%；`npm run check`、`git diff --check` 和生产依赖审计通过。本版本 CI 仍须按最终提交单独核对。

浏览器流程使用模拟权限和识别器，不能代替真实设备验收。

真实麦克风连续三轮、回声、噪声和首声延迟仍按 [设备验收清单](DEVICE_ACCEPTANCE.md) 执行，未据此宣称已经通过。
