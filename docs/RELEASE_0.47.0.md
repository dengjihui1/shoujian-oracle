# 守简 0.47.0 第二十轮自检

逐模块复核 P07 时发现：`MediaRecorder.stop()` 会先把状态设为 `inactive`，随后异步派发录音数据和停止事件。旧实现的事件回调读取实例上的音频块、录音器和媒体流；快速取消再重录时，旧回调可能混入新音频并停掉新麦克风。

现在每次录音把音频块、录音器、媒体流与自动停止计时器绑定到该次会话；旧事件只收束旧会话。回归先复现了“旧停止事件晚于新录音启动”的失败，再确认两次音频不混合且各自麦克风轨道正确释放。该异步顺序依据 [W3C MediaStream Recording 的 stop 算法](https://w3c.github.io/mediacapture-record/#dom-mediarecorder-stop)。真实麦克风及浏览器设备行为仍需设备验收。

本地 `npm test` 243 / 243、固定 RAG 集、项目检查、空白符检查和生产依赖审计通过。四组浏览器仿真首次并发运行有一条移动 WebKit 用例在点击起卦按钮前等待稳定性达到 30 秒；该用例单独复跑通过，随后单 worker 完整复跑 44 / 44 通过。此类本机性能波动仍值得在后续 CI 中观察。
