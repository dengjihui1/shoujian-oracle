# 真实设备语音验收

这一步必须由设备使用者亲自允许麦克风后执行。自动测试不能证明真实麦克风、浏览器语音服务、扬声器回声和网络环境达标。

## 一、准备

1. 使用最新版 Chrome 或 Edge，打开 `http://127.0.0.1:8000/`；正式部署时必须使用 HTTPS。
2. 确认页面显示“墨衡云端 · 周易 RAG 已连接”。
3. 第一轮用电脑扬声器，第二组再用耳机；记录浏览器、操作系统、麦克风型号和网络类型，但不要把这些写进项目日志。
4. 点击“开始语音对话（自动发送）”，只对本次页面授权麦克风。

## 二、基础样本

至少完成 10 轮，正式发布建议 30 轮：

- 3 轮短问，例如身份、日期、基础概念；
- 3 轮较长自然句，包含停顿和口头语；
- 2 轮经传知识问题；
- 2 轮问卦后的追问。

页面会汇总最近 30 轮：

- **ASR 定稿**：从识别到句末或停顿提交点，到浏览器给出最终文字；
- **首字**：从自动送问到收到模型第一个文字分片；
- **首声**：从自动送问到第一段实际朗读开始。

建议发布门槛如下；这是产品验收目标，不是当前已测结果：

| 指标 | P50 | P95 |
| --- | ---: | ---: |
| ASR 定稿 | ≤ 800 ms | ≤ 1,500 ms |
| 首字 | ≤ 2,500 ms | ≤ 5,000 ms |
| 极速浏览器首声 | ≤ 3,000 ms | ≤ 6,000 ms |

云端音色应单独记录；若 Gemini / Google Cloud 首声不达标，不要和极速浏览器样本混合后宣传。点击“导出延迟报告”会下载 `shoujian.voice-performance` v1 JSON，其中只有毫秒数、样本数和生成时间，没有录音、问题、回答或转写文字。

## 三、打断、回声与噪声

依次完成：

1. 墨衡正在朗读时点“打断并说话”5 次；旧声音应在约 500 ms 内停止，新问题只能发送一次。
2. 用扬声器完成 5 轮；墨衡朗读期间页面不得把自己的声音再次识别成用户问题。
3. 安静环境保持 5 分钟；不得无故自动发送。
4. 在普通办公室噪声下完成 10 轮；至少 9 轮定稿含义正确，失败后能点“重新听”或改用文字。
5. 拒绝一次麦克风权限；页面应显示可恢复错误，文字输入继续可用。

## 四、判定

可接受需要同时满足：

- 至少 10 轮有数据，正式发布用 30 轮；
- 三项 P95 达到上表目标，或在发布说明中明确标注未达标项；
- 5 次打断没有旧回答复活、重复问题或输入锁死；
- 扬声器测试无回声自问，安静环境无误发；
- 权限拒绝、识别失败、模型失败和 TTS 失败均可继续文字交流；
- 导出报告中不含任何说话内容。

未满足时保留报告，记录浏览器、设备、网络和复现步骤，再针对具体瓶颈调整；不要用自动测试结果代替这份人工验收。
