# 守简逐模块工程选择复核

范围：以 0.50.0 的源码、[模块池](MODULE_POOL.md)、对应单元/契约测试、本轮浏览器回归及[架构对标调研](OPTIMIZATION_RESEARCH.md)为基础，逐项判断当前选择是否值得替换。表中“保留”仅表示在匿名、轻量、单页面教学组件的当前目标下没有足够证据支持重构；不表示真实设备、正式部署或企业服务已验收。版本 0.48.0–0.52.0 的后续修复见各自发布记录。

## 前端 P01–P17

| 模块 | 当前方案与本轮决定 | 下一道有价值的证据或改进 |
| --- | --- | --- |
| P01 编排 | Web Component 集中协调各纯模块；0.50.0 修复状态请求重挂竞态。现阶段保留单组件入口，避免在缺少状态转换覆盖时贸然拆分。 | 给三阶段转换补组件集成回归；若继续增长，再抽独立状态机。 |
| P02 视图 | 转义文本、限制 HTTPS 来源、Shadow DOM 隔离；保留无框架模板。 | 自动截图和键盘/读屏检查，尤其是 390 px 与低端设备。 |
| P03 状态 | 纯函数按优先级选择人物状态；保留。 | 每新增状态先验证冲突优先级。 |
| P04 记忆 | `localStorage` 保存至多 24 条已完成消息，导入有大小/schema 校验并重算卦象；当前数据量不需要 IndexedDB。 | 导入前预览；真实浏览器私密模式和存储配额检查。 |
| P05 文字流 | 有界积压、可取消揭示和减少动态分支；保留。 | 测量长回答首字及追赶耗时。 |
| P06 API | `fetch` 解析 POST SSE，支持取消及长度上界；0.50.0 给状态检查传递取消信号。 | 异常代理断流与完整重试的浏览器回归。 |
| P07 语音输入 | 浏览器增量识别优先，短录音兜底；0.51.0 修复在线识别网络失败后的切换，0.52.0 补录音器异常结束和真实浏览器录音回环。 | 真实麦克风、权限拒绝、安静与噪声样本。 |
| P08 分句 | 小型确定性中文标点规则与长句软切分；保留，可直接测边界。 | 用真实回答样本评估停顿自然度，再判断是否换分句器。 |
| P09 语音队列 | 最多两句预取，严格顺序播放与取消；保留。 | 实测首声 P50/P95 和取消后的供应商成本。 |
| P10 播放 | Web Audio PCM 播放，缺失时 WAV/`audio` 降级；保留。 | 真实设备采样率、静音、爆音和蓝牙音频测试。 |
| P11 浏览器语音 | 本地可用音色优先，仍可切回云端；保留双路径。 | 各系统音色可用性、首声延迟及授权体验。 |
| P12 滚动 | 独立视口状态而非每次强制滚底；保留。 | 长会话与缩放页面的视觉回归。 |
| P13 键盘 | 纯函数处理 Enter、Shift+Enter、IME 组合态；保留。 | 真机中文输入法矩阵。 |
| P14 访谈 | 可序列化纯状态转换，最多四问且可跳过；保留。 | 用户任务测试，判断四问是否过长。 |
| P15 连续语音 | 显式开启自动发送、轮次代数丢弃迟到事件；保留可测试状态机。 | 真机回声、打断及首声指标；当前不宣称全双工。 |
| P16 动作 | 语义状态映射到轻量 CSS 动作和音量嘴型；保留双帧素材。 | 视觉回归及减少动态模式验收。 |
| P17 性能 | 仅本机汇总最近 30 轮延迟，不留文本；保留。 | 至少 10 轮真实样本，按设备分别记录 P50/P95。 |

## 服务端 S01–S13

| 模块 | 当前方案与本轮决定 | 下一道有价值的证据或改进 |
| --- | --- | --- |
| S01 HTTP/SSE | Node 原生服务壳有读入、输出、并发和总期限；当前路由规模无需换框架。 | 正式代理链路慢连接、断线、峰值压测和回滚演练。 |
| S02 提示与时钟 | 服务端上海时间、上下文预算、只读卦象与证据约束；保留。 | 固定问答集人工评价事实性，不靠不断叠提示词。 |
| S03 Gemini | 可注入 `fetch`、模型回退、流上界与异常取消；0.48.0 修复响应体清理。 | 真实供应商计费、取消和区域可用性。 |
| S04 检索 | 456 条冻结片段使用确定性加权检索；目前向量库会增加运维且难提高可解释性。 | 扩展语料后重新比较混合检索，逐条人工核查引用语义。 |
| S05 限流 | 本机内存、部署 Redis Lua 原子窗口；0.49.0 改用 Redis 时钟。 | 公开服务仍需身份、账号配额与账单预算；多实例压测。 |
| S06 兼容供应商 | 统一文字/SSE 契约，异常流主动取消；保留适配器隔离。 | 各供应商真实错误、限额及输出形态验证。 |
| S07 路由熔断 | 首字前切换供应商，首字后整轮恢复；进程内熔断满足当前单实例目标。 | 多实例运营时再评估共享熔断，避免放大故障流量。 |
| S08 TTS 缓存 | SHA-256 键、容量/TTL 上界与同句合并；保留。 | 请求断开后的共享合成取消语义尚未实现，需保证其他等待者不被误取消。 |
| S09 Cloud TTS | 官方 SDK、凭证隔离、LINEAR16 适配；保留。 | 真凭证首声与成本验收；SDK 调用取消能力需单独核实。 |
| S10 知识路由 | 弱误召回不绑定经传；白名单引用失败时只重试一次。 | 人工评估语义支持；编号合法并不等于引文支持结论。 |
| S11 请求准备 | 纯函数做清洗、边界、检索和模型输入，避免 HTTP 壳重复规则；保留。 | 新路由维度先扩返回契约测试。 |
| S12 请求来源 | 仅显式启用时信任代理头；当前 Caddy 默认忽略未受信任的外部 `X-Forwarded-*`。 | 如增加 CDN，按 [Caddy 文档](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)配置可信代理链并实测伪造头。 |
| S13 日志 | 请求 ID、字段脱敏和可选 IP 指纹；保留。 | 正式日志留存、访问权限和删除流程。 |

## 跨模块结论

优先继续的工程工作是 S08/S09 的合并请求取消语义、P01 三阶段组件集成回归和正式代理/设备验收。它们涉及共享调用或外部环境，不能只凭单测声称完成。当前没有证据支持引入向量数据库、WebRTC、3D 人物或前端框架；若产品目标转为公开收费服务，应先增加身份、成本预算、运营监控及隐私流程。
