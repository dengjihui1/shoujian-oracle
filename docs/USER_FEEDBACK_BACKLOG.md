# 用户反馈与下一阶段任务池

记录时间：2026-09-23（Asia/Shanghai）

当前基线：`0.27.0`

状态说明：本文记录用户已经确认的问题、产品判断与验收标准；列为“待实现”的内容不代表当前版本已经具备。

## 一、用户确认的问题

1. 对话区不会随新消息和流式文字自动到达最新位置，用户必须手动向下滚动。
2. 输入框不能直接按 `Enter` 发送，连续对话不顺手。
3. RAG 检索或引用校验失败时，页面直接显示“模型没有标注本轮检索来源”等工程错误；知识库范围外的问题没有自然切回普通大模型回答。
4. 起卦前没有充分了解用户真正问什么、时间范围、选项和约束，导致“硬起一卦”，解释缺少针对性和说服力。
5. 当前语音是“点一下转文字 + 可选朗读”，不是能面对面连续说话、随时打断的语音虚拟人。
6. 虚拟人动作和回应节奏过少，倾听、思考、回应之间缺乏自然过渡。

## 三、逐项验收标准

### UX-01 对话区智能自动滚动

- 新增用户消息、助手消息、流式字符和错误恢复替换时，用户位于底部附近则持续跟随到最新内容。
- 用户主动向上翻阅旧消息时不得强行把页面拉回底部。
- 用户离开底部期间收到新内容，显示“回到最新”提示；点击后恢复跟随。
- 桌面与窄屏均验证；长回答、连续三轮和 `replace` 恢复事件不得跳动或遮住输入框。

### UX-02 键盘直接发送

- `Enter` 发送当前消息，`Shift+Enter` 保留换行。
- 中文输入法处于拼音组字阶段时，按 `Enter` 只完成选字，不误发送。
- 空文本、正在录音、正在提交或不可编辑阶段不触发重复请求。
- 鼠标按钮仍保留，触屏行为不变，并增加键盘契约测试。

### AI-01 RAG 相关性路由与自然降级

- 普通生活、身份、基础知识和知识库范围外的问题直接走普通 LLM，不要求经传引用。
- 检索为空或相关性不足时自然切换到普通 LLM；页面不得展示内部错误码、引用校验术语或“模型回答已被拒绝”。
- 明确询问《周易》原文、当前卦、动爻、卦义或《说卦》时继续强制 RAG 证据，不允许用模型记忆伪造古籍原文。
- 经传问题检索到了可靠证据但模型漏标引用时，先进行一次受约束的引用修复；仍失败则用自然语言说明“本轮资料不足”，而不是冒充有出处。
- 增加四组回归：库外普通问答、库内经传问答、低相关误召回、引用修复失败。

建议决策流：

```text
用户问题
  → 是否明确涉及经传 / 当前卦？
      ├─ 否 → 普通 LLM 自由回答
      └─ 是 → 检索相关性是否达标？
               ├─ 否 → 普通常识可回答；古籍事实则诚实说明资料不足
               └─ 是 → RAG 回答 → 引用校验 → 一次修复 → 自然结果
```

### OR-01 起卦前情境访谈

- 用户选择“以此问起卦”后，不立即掷钱；墨衡先根据主题提出最多 2–4 个必要问题。
- 至少确认：具体对象或选择、希望观察的时间范围、已知选项、当前最关键约束；不为显得神秘而索取无关隐私。
- 系统生成一张可编辑的“问卦摘要”，由用户确认后冻结，再进入三钱六爻。
- 卦象仍由随机源和纯计算产生，用户文字不得控制卦象；针对性来自访谈后的解释上下文，不伪装成文字改变天意。
- 支持“信息已经足够，直接起卦”和“暂不回答该问题”，避免把访谈变成强制审问。
- 会话刷新后能恢复访谈进度和已确认摘要，旧版卦象快照仍可读取。

### OR-02 八字不能硬塞进三钱六爻

- 当前三钱六爻并不要求生辰八字；强制索取会混淆术数体系，也会扩大个人敏感信息收集。
- 如果以后增加八字，必须作为用户主动选择的独立模式，使用经过验证的历法 / 排盘引擎和独立知识来源。
- 出生日期、时间、地点等数据默认只存本机；上传前必须明确告知用途和范围，并提供不填写仍可继续的路径。
- 在上述条件完成前，只实施 OR-01 情境访谈，不声称当前项目具备八字能力。

### VO-01 直接语音对话模式

- 保留现有文字模式，同时新增独立“开始语音对话 / 结束语音对话”入口。
- 浏览器实时识别持续显示 interim 文本，VAD / 停顿判断一句结束后自动提交，不要求每轮再点击“发送”。
- 助手流式回答到首个可朗读短句即开始 TTS；新一轮用户开口能够打断当前回答、合成请求和播放队列。
- 网络、识别或 TTS 失败后仍能继续文字交流；页面清楚显示“倾听 / 听清 / 思考 / 说话 / 被打断 / 重试”。
- 记录 ASR 定稿、首文字和首声音的 P50 / P95；真实设备数据未达到阈值前不宣传“实时”。
- 自动提交是显式可关闭选项，避免环境噪声把私人谈话误发给模型。

### AV-01 虚拟人动作与对话感

- 用统一状态机驱动至少：待机呼吸、眨眼、倾听靠近、听清点头、思考停顿、开口说话、被打断收声、卦象展示。
- 动作由会话、音频能量和语义阶段触发，不使用与状态无关的随机大幅循环。
- 说话嘴型继续跟随音频；没有声音时闭口，网络等待时不假装正在讲话。
- 优先使用轻量分层帧 / CSS 动作完成第一版；是否升级 Live2D 或 VRM 另做性能与许可评估。
- 连续三轮语音、用户中途打断和 TTS 失败时，人物状态都必须回到可继续交流的稳定状态。

## 四、完成定义

每一项只有同时满足以下条件才可从“待实现”改为“完成”：

1. 行为代码已实现，相关模块职责没有重新堆回单一大文件；
2. 自动化回归通过，并保留能复现原问题的测试；
3. 在真实页面完成桌面和窄屏验证；涉及语音时还需真实麦克风验证；
4. `npm test`、`npm run eval:rag`、`npm run check` 和 `git diff --check` 通过；
5. 质量基线、模块池和学习指南同步更新；
6. 独立 commit 并推送，GitHub Actions 成功后才报告完成。
