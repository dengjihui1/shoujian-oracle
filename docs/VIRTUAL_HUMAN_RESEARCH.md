# 虚拟人研究与实现说明

本文记录从 0.8.0 开始为什么从聊天框升级为轻量 2.5D 虚拟卦师，以及参考边界。0.11 的多供应商、VAD / WebRTC、ASR / TTS 与性能对标另见 [性能与虚拟人架构调研](OPTIMIZATION_RESEARCH.md)。

## 一、最终选择

墨衡由两张同尺寸透明 WebP 组成：闭口人物作为稳定底层，开口人物只裁切嘴部区域叠加。八卦光环、呼吸、状态灯和音量柱由 CSS 绘制；Web Audio 对 24 kHz PCM 做实时 RMS 音量分析，音量直接控制开口层透明度。

这不是简单的“播放时循环张嘴”：静音和停顿会闭口，音量变化会同步反映在嘴部和音量柱。人物同时具有九种明确状态：静候、倾听、辨音、推演、润声、开口、失声、问已收、照卦。TTS 配额或网络失败时会明确显示“失声”，但不锁住文字对话。状态优先级集中在 `src/avatar-state.js`，可独立测试。

## 二、TTS 为什么变快

旧链路必须等完整回答结束，再把整段文字交给一次 TTS。0.8.0 改成：

```text
Gemini SSE 分片
  → SentenceSegmenter 累积到第一个完整句
  → StreamingSpeechQueue 立即合成该句
  → 同时预取下一句（总并发上限 2）
  → 按句号严格顺序播放
  → Web Audio 实时音量驱动人物
```

分句器识别中英文终止符，并在达到约 72 字时优先从逗号附近切开，以更早触发首句合成；送入 TTS 前会移除 RAG 源号、Markdown、网址和页面已展示的免责声明，但屏幕文字及来源展示保持原样。队列允许单句失败后继续，不让语音故障拖垮文字回答。

0.11 又在服务端增加相同句子的并发合并和有界 LRU / TTL 缓存。真实测试中，同一句 TTS 首次合成约 6.1 秒，缓存命中约 9 毫秒；这不会消除第一次生成的供应商时延，但能显著减少常见重复句的等待与配额消耗。

每轮回答有独立取消边界。新问题、停止回答、关闭语音、重置会话或组件卸载都会中止尚未完成的 TTS 请求、停止当前声音并丢弃后续句子，因此旧回答不会混入下一轮。

## 三、调研过的开源方向

调研日期：2026-09-21。

| 项目 | 借鉴的思想 | 本项目为何没有直接引入 |
| --- | --- | --- |
| [dengjihui1/Cactus](https://github.com/dengjihui1/Cactus) | LLM 流按句送入 TTS、播放队列、取消令牌淘汰旧语音 | 主项目技术栈和业务状态更重；这里只重写通用调度思想 |
| [TalkingHead](https://github.com/met4citizen/TalkingHead) | 音频队列、实时人物表现、viseme 驱动方向 | 3D 资源与运行时对轻量教学组件过重 |
| [HeadAudio](https://github.com/met4citizen/HeadAudio) | 浏览器音频分析驱动面部表现 | 本项目只需双帧嘴部叠层，不需要完整头像 SDK |
| [three-vrm](https://github.com/pixiv/three-vrm) | VRM 角色管线与动画状态设计 | 会引入 Three.js、VRM 模型和更高 GPU／下载成本 |
| [pixi-live2d-display](https://github.com/guansss/pixi-live2d-display) | Live2D 渲染和模型动作方向 | Cubism 运行时及模型资产存在额外许可边界，不适合当前开源包 |
| [GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) | 自定义中文音色的后续可能性 | 本地模型、显存与部署成本过高，不符合“下载即运行”目标 |

上述调研只用于架构取舍。仓库没有复制这些项目源码；实际实现是原生 Web Component、CSS、Web Audio 和本项目测试组成的零依赖代码。

## 四、许可与素材边界

- `assets/avatar/moheng-neutral.webp` 与 `moheng-speaking.webp` 为本项目独立生成的虚构人物素材，不对应现实人物；
- 开源仓库只包含压缩后的运行素材，不依赖 Live2D、VRM、Cubism 或第三方人物模型；
- 项目代码按 MIT 发布；经传冻结数据的来源和 CC BY-SA 说明仍以 `knowledge/README.md` 为准；
- 未来若替换成第三方模型、声音克隆或真人形象，必须单独核对模型许可、声音授权、肖像权与商用范围。

## 五、继续升级时的边界

可在不破坏轻量定位的前提下增加更多嘴型帧、眨眼帧或基于频段的口型映射，但应保留以下约束：

1. 人物动画故障不得阻塞文字对话；
2. 语音失败不得生成替代结论；
3. 所有网络 TTS 都必须可取消；
4. 新素材必须登记来源和许可；
5. 不为了“像真人”采集或克隆未经授权的真实人物声音与形象。
