# 守简 0.51.0 语音故障修复

用户真实页面出现“浏览器实时转写网络不可用”。根因是浏览器暴露 `SpeechRecognition` 接口，但背后的在线识别服务返回 `network`；旧逻辑只在接口不存在时启用录音兜底，连续模式的“重新听”仍走失效接口。

本轮在 `network` 错误后停用本次页面的浏览器实时识别，结束连续模式及自动朗读，展示可执行的录音提示。用户点击“按下说话”，说完点击“停止并转文字”，音频才会上传 `/api/transcribe`，返回文字进入可编辑输入框。这个兜底需要每轮手动操作，不能称为自动连续语音对话；刷新页面会重新尝试浏览器实时识别。

回归先在旧实现失败，修复后新增识别器单测，以及连续模式、单次语音和无录音能力三条页面流程。自动测试中的录音与浏览器识别是模拟的，只检验错误切换及页面状态，不证明用户设备的麦克风可用。

2026-09-25 的本机真实云端接口回环以新生成音频调用 `/api/speech` 和 `/api/transcribe`：TTS 约 5.8 秒，转写约 4.7 秒；“守简语音回环测试”返回“手写语音回环测试”。这证明当时配置下两条服务接口可调用，也暴露专有词误识别；单样本不支持准确率或低延迟结论。

本地门禁：`npm test` 246/246，`npm run check` 通过，`npm run eval:rag` 的 recall@4 与负例精度均为 100%，`npm audit --omit=dev --audit-level=low` 发现 0 项漏洞。Chromium、WebKit 的桌面和移动项目先完整通过 56/56；随后新增的无录音能力用例在四项目再通过 4/4。本机 Firefox 在启动浏览器时就报 `spawn UNKNOWN`，未进入页面断言；Linux Firefox 由远端 CI 验证。真实麦克风、权限、噪声、扬声器回声和真人连续对话体验仍按 [真实设备语音验收](DEVICE_ACCEPTANCE.md) 检查。
