# 守简 0.43.0 第十六轮自检

此前供应商单次调用有超时，但一次聊天可能连续切换多个模型或供应商，还可能再执行引用修复，导致整轮持续过久并占住云端并发名额。现在流式与非流式聊天都共享单轮总期限，默认 90 秒；达到期限会取消上游、返回稳定的 `timeout` 错误并释放名额。客户端在非流式请求中途断开时也会取消上游。正常完成时移除定时器和连接监听。

定向回归让两种聊天模式等待取消信号，确认超时分类及之后的容量恢复；另验证引用修复沿用原期限、非流式断开取消上游。这限制服务端工作时长，但真实供应商多模型切换的延迟分布和成本仍需测量。

本地 `npm test` 234 / 234、Chromium / WebKit 及两组移动仿真 44 / 44 通过；固定 RAG 集 recall@4 与域外负例精度均为 100%，项目检查、空白符检查和生产依赖审计通过。真实设备、生产代理链路与供应商账单仍待验收。
