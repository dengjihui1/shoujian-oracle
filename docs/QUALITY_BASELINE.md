## 四、当前可接受标准

以下条件同时满足时，当前版本可作为 GitHub 开源教学项目发布：

- 全量测试、RAG 评测、项目体检和空白符检查全部通过；
- 无密钥时仍可本地起卦，有密钥时自由聊天、RAG、流式文字和 TTS 契约可用；
- 生意、投资、医疗、法律、感情等主题可以起卦但不输出专业指令或保证结果；即时人身危险会转现实危机支持；
- 经传回答有白名单来源，未知内容不伪造引用；
- 密钥不进入浏览器、仓库或错误响应；
- 回答成功、断流、主动停止和配额失败后都不会锁死输入；最终失败提供用户触发的重试入口。
- 连续语音只有用户显式点击带“自动发送”的入口后才启用；回答与朗读期间停止识别，打断可淘汰旧回答和音频，失败时文字输入仍可用。

## 五、仍未覆盖的生产风险

这些不阻塞本地开源版，但在面向公众收费或长期托管前必须处理：

- 未完成 Chrome、Edge、Safari 和移动端的自动化浏览器矩阵；
- 麦克风权限、噪声环境、回声消除和不同设备的 ASR 定稿 / 首字 / 首声 P50、P95 仍需用户设备实测；本版本只显示单轮指标；
- 当前内存限流不支持多实例，生产环境需要共享限流、成本配额和滥用防护；
- 需要正式 HTTPS、反向代理、健康检查、结构化脱敏日志和供应商故障监控；
- Gemini 与可选兼容供应商的额度、区域可用性和模型容量会变化；
- 当前只有单次实测而非长期监控；生产环境仍应按场景记录首包、总耗时、TTS 首声的 P50 / P95。
- 当前未配置用户 Google Cloud 凭证，因此同步 Cloud TTS 适配器尚未做真实调用和延迟验收；Cloud STT v2 / TTS `StreamingSynthesize` 也尚未接入。Gemini API Key 不能替代这套 Cloud 配置。

## 六、每次发布前复验

```bash
npm test
npm run test:e2e
npm run eval:rag
npm run check
git diff --check
```

然后至少人工完成：连续两轮自由聊天、一次经传问题、一次起卦、一次停止回答，以及一次 TTS 失败后继续文字聊天。具备麦克风权限时再完成连续三轮语音、一次中途打断和一次 TTS 失败后的文字降级。生产发布还应完成 `docs/MODULE_POOL.md` 后续迭代池中的 P0 / P1 项。
